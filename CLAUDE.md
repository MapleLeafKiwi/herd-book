# Herd Book

Offline-first cattle tracker used by ranch crews on phones in the stockyard, often with no signal. Owner: Matthew (GitHub MapleLeafKiwi). The people using it are ranchers and farm hands, not technical users: keep wording plain and the phone UI big and simple.

Live app: https://mapleleafkiwi.github.io/herd-book/ (GitHub Pages, deploys from `main`, root folder, about a minute after a push).

## How it fits together

- **App** (`index.html`, `app.js`, `sw.js`): a plain HTML/JS installable web app, no build step, no framework. Matthew can't run builds, so keep it that way. `index.html` holds the markup and all CSS (tokens on `:root`, light and dark). `app.js` is one IIFE with sections marked `// ---------- name ----------`.
- **Data on the phone**: everything is read from `mirror` (last copy from the sheet, in localStorage) with `outbox` (unsent changes) applied on top by `recompute()`. Every edit goes through `put` / `patch` / `remove` → `queue()` → outbox → `sync()`. Never write to `mirror` directly from UI code. Every change gets an `oid` so the sheet applies it once.
- **Service worker** (`sw.js`): caches the app so it opens with no signal. **Bump `CACHE` (herdbook-vN) on every release** or phones keep the old files. The collar scanner files in `ocr/` sit in their own cache (`herdbook-ocr-1`) that survives app updates.
- **Sync script** (`sheet-script/Code.gs`): Google Apps Script bound to Matthew's "Herd Book admin" sheet, deployed as a web app (Execute as: Me, Access: Anyone). One script serves every ranch:
  - The admin sheet's **Ranches** tab lists each ranch: name, full-access code, crew code, Active tick box, its own sheet.
  - "Start a new ranch" in the app (needs the sign-up code) creates that ranch's own Google Sheet.
  - Sync is `POST {code, since, ops}` → applies ops, returns changes since `rev`, plus field-level clash reports (each op carries `base`, the values the phone last saw).
  - The `_sync` tab records applied change ids, so a change uploaded by two phones (after a QR swap) only counts once.
  - A new field on an existing record needs no script change: columns are added automatically. A new kind of record (a new collection or tab) needs `TABS` and `ORDER` entries in the script, plus `COLS` in `app.js`.
- **Roles**: full-access phones see money. **Crew phones must never receive prices**: `CREW_HIDE`, `CREW_BLOCK` and `forCrew_` strip them on the server before sending, and crew writes to money fields are dropped. The app also hides money UI (`fin()`), but the server is the guarantee. QR swaps strip money too (`shareableOps`). Keep all three when adding anything money-related.
- **Updating the live script**: Matthew pastes the new `Code.gs` into Apps Script, then goes to Deploy › Manage deployments › edit › **New version** (never "New deployment", which changes the URL). Tell him plainly whenever a change needs this.

## Features (where to look in app.js)

Work Cattle (section `// ---------- work cattle`, `#work`): a day setup ("What are you doing today?") kept on the phone per ranch (`herdbook.app.day@code`) until Finish: Fit collars, Treatment (one or more products, fields shared with Health via `treatFields`/`readTreat`, cost on full-access phones only), Preg check, Branding, Ear tag, Weigh (lb), AI breeding, Castrate, Move to group, Note, custom jobs, optional groups. The working screen IS the fitting screen (`renderFit`, one workflow): with only the collar job (and Collars › Fit collars, `#fit`) it behaves exactly as the old fitting screen; with other jobs the animal side lists who is still to come through (search finds calves by the mother's collar/brand/tag, photo search, "+ New animal here", "Animal not known (lost tag)" when collaring), and the bottom bar (`renderPanel`) shows every job ticked for the picked animal; "Done" (`workDone`) saves at once through put/patch: treatments as one record per product per phone per day (`wc…` ids, animalIds added as animals go), AI as one exposure per phone per day, preg records, brand1/brand2, vid/eid (asks before replacing), `weight`/`weighedAt` (shown in the animal's details and filled into eShepherd's Weight (lb) / Weighed date), kind → steer, group, dated notes; the animal gets `lastWorked` (date) and `workedKey` (date + hash of the day's jobs) so phones with the same jobs share the done list. Each animal's undo steps are kept in the day, so going back to a done animal replaces what was ticked. Finish shows head processed, per-job counts (this phone), not processed and withdrawal dates. Health: Record treatment takes several groups and has a picker with big ticks, Select all shown and Clear; Herd select mode has "Record treatment".

Herd list (by visual tag, collar icon when fitted) and animal form (Group is a pick list: No group, existing groups, + New group; a typed name matching a group ignoring capitals and spaces uses that group); groups (no collection: a group exists while animals have it in their `group` field, so no script change): Herd "Select" mode with big tick boxes, Select all shown / Clear, tick by collar numbers or ranges (`parseNums`), bottom bar "Move to group"; moves are one `patch` per animal inside `bulk()` (one save and redraw) with one change-log line and Undo; "Manage groups": + New group (nothing saved until cattle are moved in), Add cattle, Rename (sold animals too; asks to merge when the name matches another group), Empty group (on-hand animals to No group); Collars (collar list with three statuses shown: Fitted, Not fitted, Lost — stored data unchanged: `collar`/`collarOn` on the animal, collar `status`; "Last on" for a not-fitted collar a cow still holds; take off, mark lost/found; neckband serials; new season) and the Fit collars screen (`#fit`, old `#yard` links land here: pick a collar and a cow in either order, auto-pairs last season's collar, Fit with Undo, two lists side by side on wide screens, one at a time on a phone; the animal side is called "Animals" and wording stays neutral, never she/her/cow); collar order ("Order collars" on the fitting screen; never mention fences): each collar's place in the line is `seq` on the collar record ('' = not in line; sent with an empty `base` so reorders never raise clashes), set by typing numbers/ranges (`parseNums` keeps backwards ranges backwards), scanning, and dragging by a grab handle (pointer events, works with touch; the row lifts with scale, shadow and a slight tilt, follows the finger, the others slide into exact slots measured at pick-up, and it settles into the gap on release before the order is saved; reduced-motion skips the animation; arrow keys on the handle too); "Scan in order" (Order collars screen only; every other photo button stays one photo then tap the right number): an in-app camera with one shutter (`openScanRun`); each photo takes the next place at once and is read in the background one at a time by the same `readSerial` as the photo buttons, matched to a collar by number or neckband serial; rows needing a look say "Check" with the reason (no number, more than one number, not in the list, already in the line, fitted or lost) and open to pick, type or Remove; Done appends in photo order (asks Fix them / Leave them out); photos stay in memory only, never synced; if the camera won't open it falls back to the Photo button; `__herdbook.scanRun` is a test hook; with an order the first collar is auto-picked as "Next collar" with Skip (to the back) and Lost, fitting takes it out of the line, and last-season pre-picking is off (shown as a note); "Clear collar order" and new season clear `seq`; collar on an unknown animal (lost ear tag): "Animal not known (lost tag)" on the fitting screen stores `unknownAt` (date), `unknownGroup`, `unknownNote` on the collar record, never a placeholder animal, so herd counts, exports and breeding lists are untouched; it counts as Fitted; Collars tab notice opens a work-it-out helper listing likely animals (on hand, not calves, no fitted collar, in that group if given); "This is the one" fits it, clears the unknown fields and adds "Ear tag lost [date], needs a new tag." to the animal's notes; new season clears these too; Log (ranch name dropdown to switch ranches, each ranch has its own copy on the phone under `…@code` keys; swap with nearby phone; share); Breeding (exposures by bull or AI, calving window = dates + gestation, default 283; preg checks; calving adds a calf); Health (treatments, withdrawal, boosters); Money (full access only: sales, purchases, expenses, profit $ and %); Log (ranch and phone setup, Share with crew or full-access QR, import/export, change log);
